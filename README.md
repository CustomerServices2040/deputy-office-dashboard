# شاشة المتابعة لمكتب نائب الرئيس

مشروع مستقل داخل `CustomerServices2040/deputy-office-dashboard` فقط. لا يعتمد على مستودعات بوصلة المتعامل أو إعداداتها ولا يغيّر أي مشروع آخر.

## حالة التشغيل

- واجهة HTML/CSS/JavaScript جاهزة للنشر من جذر فرع `main` عبر GitHub Pages.
- مواضيع مرسال، البريد الإلكتروني، البحث والفلاتر، الرسوم، احتساب 14 يوم عمل، وتصدير CSV.
- المعاينة تستخدم بيانات توضيحية مؤقتة في الذاكرة، لا تُحفظ ولا تمثل بيانات المكتب.
- **الحفظ المشترك وتسجيل الدخول التشغيلي غير مفعّلين حتى إتمام ربط مشروع Firebase مستقل.** لا توجد بيانات عمل أو كلمات مرور في هذا المستودع.

## تفعيل Firebase

1. أنشئ مشروع Firebase مستقلًا لهذا التطبيق، أو اربط إضافة Firebase لإتمام الإعداد بمساعدة ChatGPT.
2. أضف تطبيق Web إلى المشروع. ضع إعدادات Web العامة في `firebase-config.js` بدل `null`. هذه الإعدادات العامة ليست مفاتيح إدارة ولا تغني عن قواعد الأمان.
3. فعّل Firebase Authentication بطريقة Email/Password. أنشئ مستخدم المكتب يدويًا، واستخدم `deputyoffice@office.invalid` كمعرّف افتراضي داخلي (ليس بريدًا مؤسسيًا ولا صندوق بريد فعليًا). حدّد كلمة المرور في Firebase فقط؛ لا تضعها في المستودع.
4. انسخ UID لهذا المستخدم إلى `officeUid` في `firebase-config.js` وإلى الموضع `REPLACE_WITH_OFFICE_UID` في `firestore.rules`.
5. أنشئ قاعدة Cloud Firestore في الوضع المغلق، وانشر ملف القواعد المرفق. القواعد تسمح لحساب المكتب المحدد فقط بقراءة/إضافة/تحديث `officeTopics`، وتمنع الحذف وجميع المسارات الأخرى.
6. أضف نطاق GitHub Pages الخاص بالحساب إلى Authorized domains إذا تطلب إعداد Authentication ذلك. راجع إعدادات سياسة كلمات المرور قبل تعيين كلمة المرور المتفق عليها.
7. تحقّق من السماح باتصالات SDK من `www.gstatic.com`، وAuthentication من `identitytoolkit.googleapis.com` و`securetoken.googleapis.com`، وقاعدة البيانات من `firestore.googleapis.com` عبر شبكة المؤسسة.
8. اختبر الدخول، الإضافة، التعديل من جهازين، تعارض التحديثات، والخروج، ثم ابدأ إدخال بيانات العمل.

اسم المستخدم المعروض هو `deputyoffice`. اسم الموظف المُدخل عند الدخول اسم تعريفي يدوّن مع آخر تعديل؛ لا يمثل إثبات هوية مستقلًا عند استخدام حساب مشترك. جلسة Firebase تخص جلسة المتصفح وتُغلق بزر تسجيل الخروج. تحديث الشاشة كل 10 ثوانٍ، مع معاملة Firestore لمنع الكتابة فوق تعديل زميل قديم.

## قاعدة أيام العمل

يبدأ العد من اليوم التالي للوصول. الجمعة والسبت مستبعدان. يصبح الموضوع المفتوح متأخرًا عند تجاوز 14 يوم عمل؛ اليوم الرابع عشر نفسه ليس يوم تأخير. المواضيع المنجزة ومواضيع البريد الإلكتروني لا تدخل قائمة التأخير التلقائية.

## النشر المعزول

من **Settings → Pages** داخل **هذا المستودع فقط**: اختر `Deploy from a branch` ثم `main` والمجلد `/ (root)`. لا تغيّر أي إعداد في مستودع آخر. ملف `.nojekyll` يتيح عرض الملفات كما هي. لا توجد إعادة توجيهات إلى المشروع السابق أو اتصالات بالخادم القديم.
